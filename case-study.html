01 · Business Problem

Commercial activity existed, but the operating trail was fragmented

The analysis focused on visibility, ownership, and data integrity—three practical issues that affect follow-up quality in an export sales process.

01

Records lived in separate places

Customer details, quotations, follow-up notes, and order files were handled across messages and documents, without one consistent customer history.

02

Status and ownership were unclear

Teams could not quickly confirm the latest quotation version, next action owner, due date, or whether an order had passed the required approval gate.

03

Exceptions were hard to control

Blank fields, duplicate inquiries, invalid dates, and premature workflow jumps could create rework or move incomplete records downstream.

02 · Discovery

The supplied documents changed the model before development

The work started by identifying the grain and truth status of each record—not by selecting charts or generating interface copy.

Finding 01

Plan and execution are different grains

The 56,480-unit schedule is the full order plan; the 17,132-unit shipment list is one execution record. They remain related but separate.

Finding 02

BOM is not sellable quantity

216,052 component and packaging units cannot be counted as finished-product sales volume.

Finding 03

Truth status belongs in the data

Operational quantities are anonymized source evidence; customer, destination, price, quotation, PI, payment and production fields are synthetic.

Evidence ruleDemonstration data has been anonymized or synthetically generated.

No customer-identifying PO, SO, booking or container reference is published.

Automation rule exampleIf a follow-up is still open after its due date, mark it overdue and place it in the sales owner's action queue. An order cannot enter production merely because its PO was approved.
Trigger

Inquiry write succeeds

Create or match Customer, store Inquiry, return the backend ID, then open the WorkflowCase. A failed write never shows false success.

Scheduled check

Follow-up becomes due

Place pending and overdue items in the sales owner's queue with the next action visible.

Controlled transition

Commercial gates pass

PO, deposit, manager release and finance sign-off must pass before production; five negative-path tests enforce the rule.

Integrity

10 · Reflection

The case is credible because its limitations are visible

Implemented behavior, source-backed evidence, synthetic demonstration data, and future architecture are deliberately separated.

What worked

One traceable operating spine

Plan, shipment, CRM records, imports and workflow tests can be followed from source to implementation.

Current limitation

Persistence is transitional

Operational collections still use a Prisma-backed StoreCollection JSON bridge; normalized PostgreSQL tables remain the migration target.

Open UAT gap

Duplicate inquiry review

The production business key and audited override path are not implemented, so this remains disclosed rather than marked passed.

Next steps

Extend only when the evidence supports the next decision

Forecasting is a planning roadmap, not a finished claim.

Digitize all 171 BOM rowsUse an approved spreadsheet or redacted PDF with page and row references.
Normalize PostgreSQL / Prisma persistenceAdd foreign keys and row-level duplicate controls.
Add explainable demand planningNaïve baseline → moving average → MAE / MAPE / bias → reorder and capacity action.
